How our pipeline works

This explainer walks through every stage of the system so you can understand exactly what happens to each request from the moment it arrives until the response is written back to the client, including retries, caching and logging.

Step 1: Ingest

input

The ingest() worker reads queue.jobs and writes to raw_events using BATCH_SIZE.

Config lives in config/ingest.yaml and env.INGEST_URL.

Step 2: Validate

check

Then validate() calls schema.parse on each event and drops null rows.

Errors go to dead_letter via dlq.push().

Step 3: Enrich

transform

The enrich() step joins users with accounts on user_id.

Cache key is enrich:v2:{id} with TTL=300.

Step 4: Store

output

Finally store() upserts into events_clean and emits event.stored.

Metrics: store.latency_ms and store.errors.

Step 5: Notify

webhook

The notify() job posts to WEBHOOK_URL with retry=3.

Signed with HMAC_SHA256.

Step 6: Archive

cold

Nightly archive() moves rows older than 90d to s3://archive.

Runs at 02:00 UTC.
